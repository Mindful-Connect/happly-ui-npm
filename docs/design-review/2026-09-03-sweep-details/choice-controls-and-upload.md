## Out of scope, worth flagging

- `packages/registry/ui/markdown-editor.tsx:444` renders user markdown with `dangerouslySetInnerHTML={{ __html: marked.parse(value) }}`. `marked` does not sanitize, so `<img src=x onerror=…>` in the editor executes in the preview. Not an interface-skills finding, and fixing it means adding a sanitizer dependency — flagging it for the lead.
- `packages/registry/ui/file-upload.tsx` has no file-row / progress / remove-button surface at all (the brief anticipated one). Those live in `use-file-upload` consumers, not in this component — nothing to fix here.
- `emoji-dialog` is a decorative memoji dialog, not an emoji picker: there is no emoji grid, no search and no empty state, so those parts of the brief did not apply.
- `packages/registry/ui/markdown-editor.tsx:707` carries the repo's one pre-existing `react-hooks/refs` eslint error (present at `HEAD` on line 704, unchanged by this sweep).

## Second pass

### What the first pass missed (the pattern, not the instances)

Three patterns, all of them the same shape: **the first pass read class strings and stopped at the element it was editing.**

1. **It never asked what a fix does to its neighbours.** The dashed-frame rewrite put `text-stroke-sub-300` on the dropzone `<label>` so an inline SVG could read `currentColor` — which also makes stroke-grey the inherited text colour of every child a consumer puts inside `FileUpload.Root`. Same shape in `checkbox.tsx`: `invisible` classes were added next to an `opacity-0` that already did the job, so the file now carries two mechanisms for one state and neither is obviously the real one. A fix is not finished at the element it touches.
2. **It read configuration as if it ran.** `emoji-dialog.tsx` passed `duration: 0.5` into five spring transitions that also set `stiffness`/`damping`/`mass`. framer-motion ignores the duration in that combination (motion-dom `getSpringOptions`: *"stiffness/damping/mass overrides duration/bounce"*), so every one of those numbers was dead — and the two chunks that visibly collided in the entrance ladder (footer and bubble, both at `delay: 0.35`) were invisible to a reader who trusted the durations. Nobody executed the motion; nobody read the library.
3. **It fixed the *presence* of a thing and not its *behaviour*.** `aria-describedby` wiring landed in the text inputs, and the choice controls — which read the same context for `disabled` two lines above — were left announcing nothing. `role="radiogroup"` in a required FormField had no `aria-required`. And no component in the group survives a long unbroken string: `text-balance`/`text-pretty` were added to every title and description, but not one `break-words`, so a 160-character token still spills 1143px out of a radio card.

Everything below was checked against the running Storybook (:6006) through the browser: computed styles, resolved `aria-*` targets, real `Tab` key presses, live DOM after an injected XSS payload. Where a claim is source-only I say so.
