## Second pass

### What the first pass missed

Three patterns, not three instances.

**1. It read class strings, so it never asked what the browser computes.** The strings looked right; the resolved
CSS sometimes was not. `badge.tsx:17` carried `leading-none` that tailwind-merge has always stripped, because every
size variant appends a `text-*` font-size class and twMerge's `font-size` group lists `leading` as conflicting — the
class has never applied in any variant. Conversely `level-bar.tsx` set `duration-300 ease-out` in the slot but
`transition-property` in an inline style, so the utility only worked because of a line 35 lines away. This pass
resolved every touched slot through the repo's own `tv`/`cn` and diffed the output string rather than the source.

**2. It normalised motion where a duration was written down, and skipped it where one was implied.** Every
`duration-200`/`duration-300` in the group got looked at; every *bare* `transition-colors` did not — and a bare
transition in this theme is 150ms at `cubic-bezier(0.4, 0, 0.2, 1)`, i.e. ease-**in**-out, against a house rule of
ease-out in both directions. Three sites (`info-card`, `badge`, `step-indicator`) were silently off-language. Same
blind spot for the one piece of motion nobody wrote a Tailwind class for at all: the `menu-tab-bar` indicator's
easing lived in an inline `transitionTimingFunction`, out of reach of every grep the first pass ran.

**3. It checked whether states were *announced*, not whether they were *drawn*.** `pagination` got `aria-current`
and a `<nav>` landmark, and nobody noticed that a `disabled` page button is pixel-identical to an enabled one —
the component has no `disabled:` rule at all, while its two nearest siblings (both tab bars) do. Fixed-height text
containers are the same story: `status-badge` has `whitespace-nowrap` to make its `h-6` honest, `badge`, `tag` and
`avatar-group`'s counter have the same fixed heights and did not.
